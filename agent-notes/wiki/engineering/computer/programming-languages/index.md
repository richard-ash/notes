# Engineering > Computer > Programming Languages

Language design, semantics, type systems, runtimes, and the ecosystems and communities that form around languages.

## Articles

- [[programming-languages-for-agents]] — Valim's (Elixir creator, Sept 2026) account of what languages should optimize for once agents write most of the code: syntax, ergonomics and token efficiency matter far less ("building around today's limitations"), ecosystems get cheaper to build while the incentive to share weakens, and compilers survive; the tooling half argues for stronger guarantees over inference-friendly convenience (a four-way taxonomy: correct-by-construction / statically established / runtime-enforced / empirically validated), queryable program databases (SQLite/Datalog) in place of position-keyed LSPs, and BEAM-style runtime observability in place of debuggers, with locality as the property that keeps all three tractable
- [[beam-in-the-agent-era]] — McCord's (Phoenix creator, Fly.io) ElixirConf US 2026 keynote *What Comes Next*: the runtime-side practitioner counterpart to Valim's essay — he no longer writes code (one months-long Codex loop, no skills/sub-agents/MCP, 20-hour runs on a $200/month plan), agent environments go remote and agents own the cycle end to end, *production is the artifact and change is constant* (lived on staging as deploy → remsh → trace → fix → test → release → repeat all night), "language doesn't matter" inverts the moment you are on a second machine, the LLM-built BEAM infrastructure stack (EKV + CASPaxos, Group, Durable Server, SocketDist, a Bandit WebSocket reverse proxy, an Elixir network-block-device filesystem, the Sprites control plane and Breeze server-side TUIs), the twelve-years-unlearned `busy_dist_port` lesson an agent with a production remsh found in ten seconds, the confidence bar (as confident as if he had written it; fuzzing/benchmarks "free"; read by blast radius; "coding is dead, software engineering is the only thing left"), the top-down bandsaw method as his only explanation for 10–100× vs −10× on the same model, and the bet that long-running supervised stateful agents are the problem Erlang was built for, so the runtime joins the loop and hot code upgrades revive because appups are now cheap to write
