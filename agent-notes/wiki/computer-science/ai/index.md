- [[ai-code-review]] — Lawson's slow-AI-coding stance and ensemble bug-finding technique: multi-model PR review (Claude + Codex + Cursor Bugbot) with critical/high/medium/low ranking, near-zero false positives, the pre-existing-bug side quest as codebase-health subsidy, and AI velocity reinvested into quality rather than throughput
- [[decide-execute-deliver-sandwich]] — Narayanan's argument that AI won't cause mass software-engineering layoffs: work is a decide-execute-deliver sandwich and AI compresses only the middle; the layoff stories are "AI washing" (Block/Snap/Intuit, NY WARN-Act checkbox, 21%-vs-2% HBR gap); writing code was never the bottleneck (8× more code → 30% more releases); vibe coding ≠ agentic engineering; and price-elasticity may grow engineer demand
- [[enterprise-agentic-coding-adoption]] — Airbnb's DPE Summit 2025 field report (Faber & Nakhimovich): the vision-and-work-backwards rollout, ~64% of engineers materializing code via agents, the holistic three-lens measurement (sentiment + adoption + aggregate PR velocity), the four-rung skill ladder with auto-approve discipline (hold test code to prod quality, push back on the agent), parallel sessions needing cloud sandboxes over git worktrees, the IDE-first → CLI-first → invest-in-the-system arc, the Airchat vendor-agnostic wrapper + early MCP bet (12+ internal servers, paved-path auth), the failed orchestrator detour ("can't beat them, join them" → delegate to the CLI engine), "tool-calling is all you need" re-wrapping internal RAG as an MCP tool instead of fine-tuning, and six lessons (it takes a village, don't call CLI an underdog with 80% shifting CLI-ward, remove barriers, don't force editor migrations, standardize-but-not-prematurely, don't drop your standards)
- [[patron-not-wizard]] — Mollick's "patron, not wizard" framing for Claude 5 Fable (the first public "Mythos-class" model): the headline shift is relational, not just capability — autonomous models that run for hours, spawn their own sub-agent fleets (cheaper Sonnet researchers + adversarial verifier groups), and make hundreds of unsupervised judgement calls collapse the human role from *doing* to *commissioning*; steering ≠ doing, work moves from process to outcome, and the black box may be the permanent price of the power; with limits (2× Opus token cost, over-eager security guardrails downgrading to 4.8 Opus, persistent Claudisms) and the more-coders-not-fewer aside
- [[ml-research-craft]] — Vivek's "research is a stack of trainable sub-skills" essay: pick your own problems (Schulman's backward-from-the-outcome mode manufactures originality), taste as a trainable predict-then-correct muscle, upgrade inputs (old papers underpriced, read the paper not the thread, range beats depth), write everything down (Graham/Feynman/Darwin → a hypothesis-result research log), tighten the loop (research speed = speed of discovering you're wrong, tooling as first-class work, Karpathy's overfit-one-batch), stare at the outputs (Ng's read-100-failures, data bugs fail silently), tune baselines until it hurts + ablate, and compounding daily edges
- [[harness-engineering]] — Lopopolo's (OpenAI) account of building a real product with 0 lines of hand-written code: harness engineering as designing the *environment* (tools, scaffolding, docs, feedback loops, mechanical constraints) rather than the code; "humans steer, agents execute"; agent legibility as the goal ("what Codex can't see doesn't exist"); repo-as-system-of-record with a ~100-line `AGENTS.md` table-of-contents + structured `docs/` and progressive disclosure; per-worktree bootable app + Chrome DevTools + ephemeral observability stack making the running app legible (6-hour overnight runs); rigid layered domain architecture enforced by custom lints that inject remediation into context; minimal merge gates because corrections are cheap and waiting is expensive; agent-to-agent review via a Ralph Wiggum loop; "golden principles" + background GC tasks paying down drift continuously; and the strong caveat that end-to-end autonomy is a property of the harness, not the model, and shouldn't be assumed to generalize
- [[custom-harnesses]] — Claire Vo's (*How I AI*) build-your-own-harness playbook: the missing practitioner rung beneath [[ai-coding-harnesses]]/[[harness-engineering]]/[[agent-harness]] — "a harness is just code around an agent" with three parts (specific context / constrained actions / fixed outcomes), when to build one (repeated workflow, same setup + same outcomes) vs. just using Claude Code (intent pre-loaded, permissions structural not prompted, process repeats without babysitting), the live Sentry bug-triage example (Claude Agent SDK + Ink TUI + opinionated adapters for Sentry/Linear/GitHub/Vercel over generic MCP, Sonnet 4.6, a standardized artifact bundle / investigation brief), the meta-note that Opus + GPT-5.5 both *resisted* putting AI in the harness (and Codex built the agent using the Claude Agent SDK), the eight-step build checklist, and the "a wrapper is just a harness" collapse that dissolves harness-vs-normal-app
- [[finding-your-unknowns]] — Shihipar's map-vs-territory framework for agentic coding: work quality is bottlenecked by the human's unknowns (Rumsfeld 2×2 applied to prompting), with a phase-by-phase toolkit — blind-spot passes, brainstorms/prototypes, interviews, source-code references, change-ordered implementation plans, implementation-notes deviation logs, pitch/explainer artifacts, and merge-gating quizzes — plus the Fable-launch-video worked example (teach-me-color-grading over pick-a-variation)
- [[agent-failure-modes]] — Jozefiak's field guide to the six ways an agent breaks *in daily use* (not while building): the root cause is multiplicative step reliability (99%/step → 37% over 100 steps, worse because errors correlate), then overbuilding (tool-space interference, context rot, fix = prune + search-then-load), one-agent-does-everything (Anthropic-vs-Cognition multi-agent debate, cut on context seams), memory poisoning (source+date + working/durable layers + drift checks), no fallback (layered gateway + local floor, and test it), trusting without checking (check the outcome not the log line, re-run the failing thing), and never challenging it (keep a nasty-case regression suite) — all converging on harness engineering: the failure lives in the system, not the model
- [[open-source-in-the-enterprise]] — Zhang's (Decagon CEO) maturity-curve reading of open-source's *falling* enterprise LLM-spend share (11%, down from 19%): the paradox that Decagon runs 90% open source while the aggregate moves toward closed is resolved by a use-case maturity curve — new use cases buy general frontier intelligence (you don't know the problem's shape), mature ones flip to small + fine-tuned + self-hosted open weights (general intelligence becomes overhead); Decagon went open not for cost but because latency forced small+fast, which forced fine-tuning, which the frontier labs don't sell; the 11% is a denominator problem (thousands of new immature use cases spinning up faster than old ones mature); "frontier labs own discovery, open source owns production"; and the inflection up is years away because fine-tuning needs data/expertise/high-ROI-at-scale most orgs lack
- [[agentic-pods]] — Uber's (Neppalli, July 2026) program for taking agentic AI *beyond engineering* into business functions: engineering-adoption figures as the launchpad (99% of engineers on AI tools, >70% of PRs agent-authored, 2,500+ skills), then the two-week pod — one AI-proficient engineer + one domain expert, shadow (days 1–2) → prioritize (day 3) → build (4–5) → validate (6–9) → ship (day 10) — run 16 times across 16 functions with self-reported compressions (capital allocation 15h→30m, financial pacing 2d→10m, marketing QA 2w→50m); the load-bearing claim is *the workflow, not the task, is the unit of automation* (redesign the process and you delete handoffs/approvals/legacy tooling/vendor spend), and the method's own thesis is proximity-beats-documentation ("build with them, not for them"); Uber running the FDE motion internally, with open questions on maintenance/drift, no-PMs-in-the-pod, and review quality behind the 70%
- [[token-pricing]] — Evans's (July 2026) economic deep-dive under the commodity-models pillar of [[ai-eats-the-world]]: where a token's price settles once the supply crunch eases (between seller marginal cost and buyer ROI, but every input is unknown), the 40–50% inference gross margin that excludes training, the four questions that decide the outcome (how many pay for the frontier / does the frontier keep moving / is competition still fierce / how much value the model itself captures), the two poles (two-or-three giant minds vs. LLMs-as-databases), the sharper this-time epistemic caveat (no theory of *why* models work → unknown ceiling), the analogy discipline (fiber wrong twice, mobile-data as best-fit $1tr-industry-flat-stocks precedent, semis/Rock's-Law/TSMC-captures-little, Altman's contradictory Windows-vs-utility, and analogies-have-no-predictive-value), and the Trump/China *dei ex machina* whose China-closed-source kill-switch matches [[ai-lab-economics]] — bottom line: default extrapolation is commodity infra with value up the stack, and any other outcome "requires something to change" not yet visible
- [[latent-space]] — Kelly's argument that the compressed representation inside a model is a *medium*, not just a mechanism: concepts as directions you can push things along, everything on one map, books as trajectories, "the words are the thinking" (chain-of-thought *is* the reasoning, not a report of it), and a dozen speculative uses (prospect in the gaps / white-space discovery, cross-domain analogy, latent-space measurement, dissecting the space as a specimen, retro latents, infiltrators, personal latent space) — with the technical looseness flagged (parameters ≠ directions; superposition is the missing piece; `king − man + woman` is word2vec-era while activation steering is the real modern vindication; "correctness is a vector" doesn't explain when the model stops) and the tension against Evans's punk-rock objection in [[generative-ai-as-pattern-generation]]
- [[ai-and-legal-reasoning]] — the first preregistered RCT on whether AI use erodes lawyers' independent reasoning (Bednar/Cleveland/Erbsen/Schwarcz, Minnesota law students, Gemini 2.5 Pro): AI-assisted synthesis boosted quality +60% (1.2 SD) *and* improved later unaided application (+24%) via stronger intermediate work product, with no comprehension loss — but AI at the revision stage, under fatigue and a 20-minute window, degraded strong performers' memos while lifting weak ones; three best-practice principles (only use AI where you can independently assess output, confine it to narrow components, avoid it when tired/rushed) and the defend-it-to-a-skeptical-judge heuristic
- [[ai-lab-economics]] — swyx's structural account of AI labs: model labs (close to GPUs/research) vs agent labs (close to use case), subscription subsidy as marketing not P&L (gym-whales metaphor), why lab-built apps are buggy (model-lab engineers don't respect the app layer), GPU annual cycle as the actual cadence of capability progress, iterative deployment as deliberate slow takeoff aligned with Feldman's vaccination hypothesis, and "sincere yearning for science fiction" as the field's selection criterion — plus Shaughnessy's subsidy-unwind bear case (per-seat subsidy → enterprise governance forces metered API repricing → open-weights escape valve via free Chinese frontier models caps pricing power → already-negative margins leave labs dependent on capital that can flee; kill switch is China going closed-source, escape hatch is AI enabling genuinely new value)
